## 활동 1. 개인 포트폴리오 사이트 제작 {#portfolio}

### 기간과 상태

- **기간:** 2026년 11월 6일 ~ 11월 7일 (초급프로젝트 과제 1)
- **상태:** 완료. 사이트는 공개 배포 중이며, 앞으로 새 활동을 계속 추가할 예정입니다.

### 목적

웹개발을 배우면서 한 일을 한곳에 정리해 보여 줄 공간이 없었습니다. 이 활동의 목표는 두 가지입니다.

1. 로그인 없이 누구나 열 수 있는 HTTPS 주소에 저를 소개하는 사이트를 올리기
2. 내용을 고친 뒤 `main` 브랜치에 push만 하면 GitHub Actions가 자동으로 다시 빌드·배포하는 구조 만들기

### 역할

**개인 활동**입니다. 팀원 없이 혼자 진행했고, AI 도구(Claude Code)를 활용했습니다.

- **본인이 한 일:**
  - 테마 선택, GitHub 저장소 생성과 Pages 배포 설정
  - 소개·활동에 쓸 내용(관심 분야, 목표, 활동 사실)과 사진 제공
  - AI 제안의 채택·수정·보류 결정
  - 공개 사이트에서 결과 확인
- **AI 도구가 도운 일:**
  - 배포 준비, Git 커밋·push 명령 실행
  - 설정 파일, 템플릿, CSS·JavaScript 수정 코드 작성
  - 소개·활동 문장 정리
  - 점검 스크립트 작성과 자동 검증

외부에서 가져온 자료는 다음과 같습니다. 출처와 AI 활용 구분은 저장소 README에 정리했습니다.

- [Hugo Coder](https://github.com/luizdepra/hugo-coder) 테마 (MIT 라이선스)
- 수업에서 제공한 배포 준비 스크립트

### 과정과 선택 이유

각 단계의 결정과 결과 확인은 본인이 했고, 명령 실행과 코드 작성은 AI 도구가 도왔습니다.

1. Hugo Themes에서 테마를 고르고, 원본 저장소의 Download ZIP으로 받았습니다.
2. 수업 제공 스크립트로 GitHub Pages 배포 파일을 준비하고, Git 저장소를 만들어 push했습니다.
3. GitHub Pages의 배포 방식을 GitHub Actions로 설정해 첫 배포를 확인했습니다.
4. 테마의 데모 이름, 데모 글, 데모 SNS 링크, 포르투갈어 설정을 지웠습니다. 언어를 한국어로 바꾸고 메뉴를 "소개 / 활동"으로 정리했습니다.
5. 소개와 활동 내용을 작성하고, 수정할 때마다 push로 자동 배포되는지 확인했습니다.
6. 크롬 개발자도구, AI 도구로 만든 점검 스크립트(`tools/check_site.py`), Playwright 자동 검증으로 배포된 사이트를 검사하고, 발견한 문제를 고쳤습니다.
   - 도메인 루트로 가던 404 요청 2건 제거
   - 키보드로 열 수 없던 모바일 메뉴 버튼과 다크 모드 버튼 수정
   - 390px 화면에서 넘치던 홈 바로가기 버튼 수정
   - 마우스를 올려야만 보이던 제목 링크 아이콘 제거

**Hugo Coder를 고른 이유:** 슬라이더나 복잡한 JavaScript 없이 이름, 소개, 아바타, 메뉴만으로 구성된 단순한 테마입니다. 처음 만드는 사이트에서 모바일 화면과 링크 오류를 관리하기 쉽다고 판단했습니다.

### 배운 점과 개선 방향

- **배운 점:** 저장소 이름이 주소에 들어가는 GitHub Pages 사이트(`/portfolio/`)에서는 사이트 기본 주소(baseURL)가 맞아야 CSS와 이미지가 제대로 열린다는 것을 알게 되었습니다. 작은 단위로 커밋하면 무엇을 언제 바꿨는지 추적하기 쉽다는 것도 배웠습니다.
- **배운 점 2:** 테마가 기본으로 제공하는 버튼도 키보드로 조작되지 않을 수 있었습니다. 화면 폭과 키보드 조작은 직접 확인해야 문제를 찾을 수 있다는 것을 알게 되었습니다.
- **한계:** 처음에는 PC에 Hugo가 없어, 수정할 때마다 push하고 GitHub Actions 빌드(1~2분)를 기다려야 결과를 볼 수 있었습니다. 이후 Hugo 0.167.0을 받아 `hugo server`로 미리 확인했습니다. 링크·화면 폭·키보드 동작은 자동 검증으로 확인할 수 있게 됐지만, 읽기 편한지나 초점이 눈에 잘 띄는지 같은 판단은 여전히 사람이 직접 봐야 합니다.
- **개선 방향:** 점검 스크립트를 GitHub Actions에 연결해 push할 때마다 링크와 자산을 자동으로 검사하겠습니다. 겨울방학에 만들 풀스택 웹서비스도 새 활동으로 추가하겠습니다.

## 활동 2. HTML·CSS·JavaScript 기초 강의 실습 {#web-lecture}

### 기간과 상태

- **기간:** 2026년 10월 첫째 주 (1주)
- **상태:** 완료

### 목적

웹 페이지를 이루는 HTML, CSS, JavaScript를 처음부터 배우기 위해 기초 강의를 들었습니다.

### 역할

**개인 학습**입니다.

- 예제 코드는 강의(생활코딩)에서 제공한 것입니다.
- 저는 예제 저장소를 내려받아 VS Code에서 코드를 직접 수정하고 브라우저로 실행해 보며 실습했습니다.

### 과정

1. HTML로 문서 구조(제목, 목록, 링크)를 만드는 방법을 익혔습니다.
2. CSS로 글자와 배경 색을 바꾸는 방법을 익혔습니다.
3. JavaScript의 조건문, 반복문, 배열, 함수, 객체를 배웠습니다.
4. 버튼을 누르면 페이지가 야간/주간 모드로 바뀌는 기능을 실습했습니다. 반복되는 코드를 함수와 별도 파일(`colors.js`)로 정리하는 과정도 따라 했습니다.

### 산출물

- **실습에 사용한 강의 예제 저장소:** <https://github.com/web-n/web2_javascript> (출처: 생활코딩 egoing)
- **실습 결과:** HTML 문서 3개를 메뉴로 연결한 웹 페이지와, 버튼 하나로 색상 모드를 바꾸는 JavaScript 기능을 실행해 확인했습니다.

### 배운 점과 개선 방향

- **배운 점:** HTML, CSS, JavaScript를 처음 배우면서 코드가 바로 화면으로 바뀌는 점에 흥미를 느꼈습니다. 이 경험이 [활동 1](#portfolio)에서 사이트를 직접 만들어 보는 계기가 되었습니다.
- **한계:** 강의 예제를 따라 하는 수준이라, 처음부터 스스로 설계한 페이지는 아직 만들지 못했습니다.
- **개선 방향:** 배운 기능을 활용해 직접 기획한 웹 페이지를 만들어 보겠습니다. 그 다음 단계는 [소개](../about/#goal)에 적은 풀스택 웹서비스입니다.
